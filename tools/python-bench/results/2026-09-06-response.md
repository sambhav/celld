# Python response adapter: repeated A/B

A narrow JSON response fast path improves throughput another 8–17% over the
scheduler candidate, with lower p95 latency in every measured configuration.
It does not deliver TypeScript parity or an established memory/startup gain.

[GitHub run](https://github.com/sambhav/celld/actions/runs/34026428767), source
`d550ba265f4911aec83b4ce2af44e2837b490939`. AMD EPYC 7763, two physical/four
logical CPUs. Three ten-second rounds, 256 clients, one/four isolate limits,
54 samples, **2,350,025 measured responses and zero errors**. Real upstream
counts equal completed requests in every I/O sample.

Baseline: scheduler runtime from native correctness run `34024363125`, source
`fe0ca8f7dcd4f4afa48bbbcfe8ebdc04887fceb2`. Candidate: that runtime plus the
response changes. Every arm uses the same native binary from run `34019509877`,
source `37e41ff2dcd6e1097f4207406a6b5a63a8e647fc`. TypeScript is a matched control
in this run; do not compare absolute values with runs on other CPUs.

At four isolates, hello p95 falls from 104.70 to 82.53 ms; I/O 10 ms from
156.30 to 145.66 ms; I/O 50 ms from 158.01 to 144.66 ms. Python scales
2.30–2.39x between one and four isolate limits on this two-core runner.

The common `Response.from_json` path now serializes in Python and creates the
native response with one host helper call. It avoids repeated Python-to-JS
header construction, native type queries and a URL query. Custom status,
status text, headers and native JsProxy inputs keep their existing behavior.
Python JSON encoding still preserves large integers and its existing Unicode
serialization. Newly created responses have independent headers and bodies.

Native smoke passed before this comparison, including a real-interpreter
response contract fixture: large integer and Unicode roundtrips, independent
headers, body-consumption errors, custom options, JsProxy JSON, native response
wrapping and invalid Python JSON. Existing reload, Pydantic, NumPy and concurrent
async context/cancellation checks also passed. The full native build and tests
passed in [run 34026139902](https://github.com/sambhav/celld/actions/runs/34026139902).

Limits: local SQLite dev storage, warmed artifact/disk caches, no remote S3.
The load driver and real upstream share the runner CPU with celld. First hello
request after health remains around 0.7 seconds for Python versus 1.3 ms for
TypeScript; this is not idle scale-to-zero wake latency. Native process health
readiness is recorded separately and varies by seconds. RSS has no consistent
improvement. Isolate limits are configured limits, not instrumented counts of
initialized runtimes. Raw samples and CPU metadata: `2026-09-06-response.json`.
